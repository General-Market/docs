Goldilock is the oracle network that resolves nsgame markets. It reads the public data, signs the settlement, posts the signature on-chain. The Solana program will not pay out a pool until it has Goldilock's signature on the result. This is the bridge between a tube site's view counter and a winning bet.

The name is not a metaphor. The temperature is the point — neither too hot nor too cold, neither a single trusted daemon nor a thousand-node mob. A small, multi-signature, on-chain-verifiable network. Boring on purpose.

## What Goldilock is

A set of oracle nodes that agree on what the data says, sign the agreement, and post it where the program can verify it. The current architecture, in plain terms:

- **Multiple nodes.** More than one, fewer than many. Quorum is `[FACT TBD: quorum threshold — e.g. 2-of-3 today, M-of-N at mainnet]`.
- **Independent reads.** Each node fetches the data sources independently. No single node's reading is taken on faith.
- **Multi-signature settlement.** A settlement is valid only when a quorum of nodes co-signs it. The program verifies the signature against a registered set of oracle pubkeys.
- **Public readings.** Each node publishes its readings. Anyone can re-derive the resolution from the same public data and check that the signed answer matches.

What gets signed is not an opinion. It is a tuple — market id, round id, A's value, B's value, winner — derived mechanically from the data sources documented in [Data Source Methodology](/trust/data-source-methodology).

## Today

Founding-team operated. Two nodes on VPS infrastructure, one signing key controlled by the founding team. This is testnet. We are not pretending otherwise.

- **The nodes run on the founding team's servers.** Same operator, different boxes. Not a real federation. A rehearsal.
- **The signing key is held by the founding team.** Stored in an encrypted environment file on each node. Rotated when the team feels like rotating it.
- **Settlements are posted within `[FACT TBD: settlement latency window in seconds]` of round close.** When something goes wrong — rate limit, source outage, network partition — the settlement does not post and the round routes to refund. See [Refund Policy](/product/refund-policy).
- **Readings are committed to a public log.** Anyone can fetch the raw readings from the oracle node and re-compute the result. The methodology is on the [Data Source Methodology](/trust/data-source-methodology) page.

This is enough for testnet. It is not enough for mainnet.

## At mainnet

After the oracle network has been audited (see [Audit & Mainnet Roadmap](/trust/audit-and-mainnet-roadmap)), Goldilock changes shape:

- **DAO-elected operators.** Oracle slots are filled by an election. Operators stake to participate. Misbehaviour — wrong signatures, missed rounds, divergent readings — is slashed.
- **Independent operators.** The point of a multi-oracle network is that a single operator cannot capture the result. Mainnet enforces this by election, not by trust.
- **Rotating signing keys.** Each operator runs their own key. The aggregated public key is registered on-chain and rotated on a schedule the DAO sets.
- **Public dashboards.** Each node's uptime, last-seen, deviation from the median reading — all on a public dashboard. Operators with bad numbers do not get re-elected.

The DAO is in formation; details will be published when finalised. The election cycle, slashing schedule, stake size, and operator entity wrapper are TBA. We will not invent numbers we cannot keep.

## What Goldilock guarantees

Three things, narrowly.

1. **The signed settlement matches the public data.** If you read the oracle's published readings and apply the methodology in [Data Source Methodology](/trust/data-source-methodology), you arrive at the same winner. If you do not, the oracle has misbehaved and the chain is the receipt.
2. **No single node can resolve a market alone.** A quorum is required. One compromised box cannot move a payout.
3. **The Solana program will not accept an unsigned settlement.** The program verifies the signature against the registered oracle keys on every payout. There is no admin override. There is no `onlyOwner` escape hatch. See [Settlement Rules](/product/settlement-rules).

That is the surface area of the guarantee. It is small on purpose.

## What Goldilock does not guarantee

- **That the data sources are honest.** Goldilock reads xvideos, xnxx, pornhub, chaturbate. We read what they publish. They own their counters. If a tube site decides to inflate, smooth, or fabricate its view counts, Goldilock will dutifully sign the fabrication. We are a faithful reporter, not an auditor of upstream truth.
- **That the data sources stay reachable.** Rate limits happen. APIs change. Sources go down. When they do, the round refunds. See [Refund Policy](/product/refund-policy).
- **That the result feels fair.** The result is what the data says. Sometimes the data says something unintuitive — a flush, a reset, a missed update. The protocol pays the winner regardless of how the loser feels.
- **That the website agrees with the protocol.** The website may delist a market for reasons of its own. The protocol still settles. See [Subject Removal Policy](/trust/subject-removal-policy).

## How a settlement happens

In order:

1. The round closes. The market locks. No more bets accepted by the program.
2. Each Goldilock node fetches the data sources and computes the result independently.
3. The nodes exchange signatures. A quorum signs the same tuple.
4. The aggregated signature is posted on-chain as part of a `resolveMarket` transaction.
5. The program verifies the signature, marks the market resolved, and unlocks claims.
6. Winners claim their share of the pool, minus the 0.3% rake.

If step 3 does not produce a quorum — because the nodes disagree, because the data sources rate-limited some of them, because one node is offline — the settlement does not post. The round eventually times out into a refund.

## The asymmetry, named

Goldilock is the strongest part of the system and the weakest part of the system. Strongest: the cryptography is honest, the program enforces it, the readings are public. Weakest: the network is small, the operators are us, and the audits have not happened. Everything in this document trends, with effort and time, toward something more decentralized than what is true today. The audits are the gate. The DAO is the destination. Until then, you are trusting a protocol that admits, in writing, what it has not yet earned.

We would rather earn it slowly than claim it falsely.
