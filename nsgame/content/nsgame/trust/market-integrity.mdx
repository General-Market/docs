A prediction market without integrity is a casino without lights. nsgame's integrity surface is small on purpose — fewer moving parts, fewer places for manipulation to hide. This page is the inventory of those parts and the honest accounting of what each one protects against.

## What the protocol is

A parimutuel pool. Two sides, one round, one number from each subject at the start, one number at the end. Whichever side won the comparison takes the pool. The protocol takes 0.3% of each winning payout and routes it to the treasury. See [Parimutuel Methodology](/product/parimutuel-methodology) for the math, [Settlement Rules](/product/settlement-rules) for the lifecycle, [Fee Schedule](/product/fee-schedule) for the rake.

This shape matters for integrity. A parimutuel pool is structurally different from an order book.

## Why parimutuel resists the standard manipulations

Most market manipulation playbooks were written for order books. They translate poorly to a pool.

- **Wash trading.** In a CLOB, you can fake volume by trading with yourself, and the printed price moves in ways that mislead other traders. In a parimutuel pool, "trading with yourself" means putting money on both sides — which costs the rake on the winning side and contributes nothing to either side's edge. The implied odds shift, but the resolution does not. You can mislead the next bettor about the apparent skew, but you cannot move the outcome.
- **Spoofing.** Parimutuel pools have no resting orders to spoof. A bet is a commitment, not a bid. There is nothing to flash and pull.
- **Front-running.** A bet sent into the same block as another bet does not "frontrun" anything. The pool is a sum, not a queue. Order of arrival within a block does not change the payout structure.
- **Last-second price impact.** Closing seconds in a CLOB are violent. In a parimutuel pool, late bets dilute the late side and concentrate the early side's payout — which is a feature of the design, not a vulnerability of it.

What this leaves: the only attack surface that survives is the resolution. Move the resolution, and you move the payout. The rest of this page is about how that surface is defended.

## What the protocol enforces

The Solana program is the floor. It enforces what cryptography can enforce and nothing more.

- **Custody is the bettor's.** Bets sit in program accounts; payouts go to the wallet that placed them. The website cannot redirect a payout. The founding team cannot redirect a payout. There is no admin hand on the pool.
- **Settlement requires Goldilock's signature.** Resolution does not happen on a developer's say-so. The program will not pay out until [Goldilock](/trust/goldilock-oracle-network) has co-signed the result with a quorum of registered oracle keys. There is no admin override and no `onlyOwner` escape hatch.
- **The rake is fixed.** 0.3% of each winning payout. Any other distribution would require a program upgrade, which is governance-gated.
- **Refunds are deterministic.** The conditions that trigger a refund — see [Refund Policy](/product/refund-policy) — are encoded. The website cannot refuse a refund the program has authorized. The website cannot grant a refund the program has not.

This is the surface the protocol defends. It is small, on purpose.

## What the website enforces

The website is the second layer. It does what a website can do.

- **Catalog presentation.** The website displays the 25 PvP fights from the frozen catalog. It can delist a market from the UI without changing the protocol — see [Subject Removal Policy](/trust/subject-removal-policy).
- **Geographic blocklist.** The website refuses connections from a standard set of jurisdictions. The protocol does not check.
- **Age gate.** Soft, checkbox-based, plus a confirmation message after entry. The website enforces; the protocol does not see it. See [Age Verification](/legal/age-gate).
- **UI signal hygiene.** Implied odds, pool sizes, and timers are computed from chain state and shown without editorial filter.

The website is not a regulator. It is a window. When the website disagrees with the protocol — for instance, when it has delisted a subject but the protocol continues to settle — the protocol is what pays. The website is what hides.

## Goldilock's role

The oracle network is the integrity hinge. If [Goldilock](/trust/goldilock-oracle-network) signs the wrong result, the pool pays the wrong winner. The defenses against that:

- **Multi-signature.** A single node cannot resolve. A quorum must agree.
- **Public readings.** Each node publishes its readings. Anyone with the same access to the public sources can re-derive the answer — see [Data Source Methodology](/trust/data-source-methodology). Disagreement is detectable.
- **Refund as the failure mode.** When the network cannot reach quorum, the round refunds. There is no "fall back to one node" path. The system would rather give the money back than guess.
- **Audit before mainnet.** The Goldilock pipeline is audited before mainnet — see [Audit & Mainnet Roadmap](/trust/audit-and-mainnet-roadmap). On testnet, the founding team operates the network. We are honest about that.

## Residual risks, named

Honest integrity pages list what does not get defended.

- **A coordinated wager can shift implied odds.** A large bettor on one side moves the apparent skew. This is parimutuel mechanics, not a bug. The implied odds shift — the resolution does not. Other bettors can take the now-better-priced opposite side. The pool finds its level.
- **The data source can be wrong.** If a tube site decides to publish bad numbers — inflated, smoothed, fabricated — Goldilock will read and sign them. We are a faithful reporter of an unfaithful publisher, in that scenario. There is no cryptographic defense against an upstream lie. The defense is that the lie has to fool a public counter watched by everyone, not just us.
- **Goldilock is small today.** Founding-team-operated. A compromised key on our side, today, is a real risk. The audit, the DAO election, and the operator stake-and-slash are how that risk shrinks. They have not happened yet.
- **The website can mislead in cosmetic ways.** A subject can be delisted from the UI while remaining on-chain. A market can show stale UI state during an outage. None of this affects the protocol's payout, but it can affect what a user sees while making a decision.

## What integrity looks like in practice

For each round:

1. The catalog is fixed. The market exists in code, not in editorial discretion.
2. Bets accumulate in program-controlled accounts. Custody is the bettor's.
3. The round closes. The pool is the pool. No further bets.
4. Goldilock reads the public data, agrees with itself by quorum, signs the result.
5. The program verifies the signature, distributes the pool to the winning side, takes the 0.3% rake, and unlocks claims.
6. Winners claim. Losers do not.

If any step breaks — bad signature, missing quorum, source outage, contradicted reading — the round refunds. The protocol does not award a wrong answer to keep the game alive.
