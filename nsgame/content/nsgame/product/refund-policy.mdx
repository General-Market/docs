A round can fail. The data source can vanish, the oracle quorum can break, the integers can come back tied. When the protocol cannot decide a winner cleanly, it does not guess. It voids the round and returns the stakes. Refund is the answer to every failure mode that is not a winner.

## What triggers a void

| Trigger | Description |
|---|---|
| Oracle quorum failure | Insufficient signed readings to reach quorum at the resolution deadline. |
| Data source unavailable | The tube site returns errors at open or close such that no usable reading exists. |
| Source rate-limits the oracle network | Insufficient interval readings (F2) or unobtainable open/close reading (F1). |
| Source shuts down mid-round | Site goes offline and stays offline. No close reading possible. |
| Source changes its API mid-round | Layout, schema, or definition flip during the window that breaks comparability. |
| Source returns garbage | Readings are nonsensical (negative deltas, impossible counts) and disagree across nodes. |
| Tied outcome | F1 gain integers equal, or F2 aggregated totals equal at the integer level. |
| One-sided round | Stake on only one side at lock — no opposing pool to redistribute. |
| Subject removed mid-round | A subject delisted from the source platform during the window. |

Any of the above ends the round in the void state. The market shows "voided" with the reason; the chain records the void; the refund path activates.

## How refunds work

**Claim-based by default.** The program holds your stake. To retrieve it, you sign a refund transaction. The wallet that staked is the wallet that claims. There is no operator-initiated payout — the program responds to your signature, not ours.

**Auto-refund when ergonomically better.** Some void cases are unambiguous and small enough that the protocol issues refunds without requiring user action. Examples include one-sided rounds (no contest existed) and rounds voided before any meaningful trading occurred. The judgement is made per failure case; the rule is "less friction wins where the math is trivial."

When a refund is auto-issued, the wallet receives the stake without signing anything beyond Solana's normal transaction acceptance. When a refund is claim-based, the website surfaces a "claim refund" action.

## Refund mechanics

A refund returns the original stake at 1:1. No rake is taken — the rake exists only on winnings, and a voided round produces no winnings. Solana network gas applies to the claim transaction itself; the protocol does not reimburse gas.

Refunds do not pay interest, do not adjust for time-value, do not include any compensation for the inconvenience of the void. The stake comes back. That is the contract.

## Claim window

Refunds do not expire. The program holds the void state until claimed; a wallet that walks away can return weeks or months later and retrieve. There is no sweep account, no operator wallet that absorbs unclaimed funds, no "house keeps it" clause. [FACT TBD: whether a finite claim window will be introduced before mainnet]

## How a void is announced

Three paths, in order of immediacy:

1. **On-chain event.** The settlement transaction posted to the on-chain program signals the void state directly. Anyone watching the chain sees the void at the same time we do.
2. **Website notification.** nsgame.org marks the affected market with the void reason and surfaces the refund action to wallets with stake in the round.
3. **Status notes.** Persistent or pattern-level source issues — a site removing a public metric, a parser change requiring redeploy, an oracle node taking time to recover — are noted on the website and in the [Data Source Methodology](/trust/data-source-methodology) changelog.

The chain is the canonical source. The website mirrors the chain. If the two disagree, the chain wins.

## What is not refundable

- **A round you lost.** Losing is not failing. The protocol resolved cleanly; you were on the wrong side. No refund.
- **A wager you regret.** A staked wager is committed. The protocol cannot un-stake it before lock; it certainly cannot after.
- **Solana network fees.** The chain charged gas. The protocol did not collect it and cannot return it.
- **Wallet-side errors.** A wallet that signed a stake to the wrong pair, the wrong side, or the wrong amount staked what it staked. The protocol enforces the program's rules; it does not interpret intent.
- **Off-chain expectations.** A bettor who believed the round would void because of a source issue, but where the oracle resolved cleanly anyway, has no claim against the resolution. The signature is the answer.

## Special cases

**Partial source failure.** A round where some oracle nodes got readings and others did not — but quorum was still reached on the side that read — resolves normally. Quorum, not unanimity, is the bar. Below quorum, the round voids.

**Late-arriving signature.** If the aggregated signature lands on-chain after the resolution deadline, the program rejects it. The round voids. There is no "almost made it" — the chain enforces the deadline.

**Reorg or chain instability.** Solana finality is the standard. The protocol treats a confirmed transaction as final and does not re-evaluate after deeper block depth.

**Void that splits pool unevenly.** Refunds are 1:1 stake. The pool was never converted into winnings; the math is trivial. Each wallet gets back what it put in.

## What a voided round costs the protocol

Nothing the protocol minds. The rake is zero on a voided round. The oracles ran but did not produce a settlement. The DAO treasury does not grow. The bettors are made whole. The only cost is the gas on the void transaction and the time spent — both of which are absorbed.

A void is the protocol working as designed. A void is not failure; failing to refund would be failure.
