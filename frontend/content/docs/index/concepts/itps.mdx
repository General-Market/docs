# Dex Traded Funds (DTFs)

A DTF (Dex Traded Fund) is a tokenized basket of up to 100 crypto assets with fixed per-share quantities, priced by a single number called NAV (Net Asset Value).

- Holds 1–100 assets with defined weights
- Each share = fixed quantities of each underlying asset
- Implements ERC-4626 (the standard vault interface)
- Deployer earns fees; protocol mints/burns shares 1:1 against backing

## Quick Start: Buy a DTF

## What Makes Up a DTF

Four components:

- **Basket of assets** — up to 100 crypto assets with defined weights
- **Fixed per-share quantities** — each share represents a fixed amount of each underlying asset
- **ERC-4626 vault token** — standard vault interface, composes with the rest of DeFi
- **Deployer** — the address that built the basket and collects fees

<Info>
Up to **100 assets** per basket. Build a market-wide index or a narrow conviction play. The protocol does not gate allocation choices.
</Info>

## NAV Pricing

NAV (Net Asset Value) is the fair value of one share, computed from the prices of every asset inside the basket. It is the single number that drives every buy and every sell.

### NAV Computation Formula

```solidity
NAV = sum(qty[i] * price[i]) / 1e18
```

Where:
- `qty[i]` is the fixed per-share quantity of asset `i`
- `price[i]` is the current market price of asset `i`
- Division by `1e18` normalizes to a human-readable value

The same formula runs in three places: on-chain in `Index.sol`, off-chain in the oracle nodes, and in the frontend. If the three ever disagree, the protocol is broken.

## DTF Creation: How Quantities Are Set

Every DTF launches at exactly **$1** per share (`1e18` in contract math). The deployer chooses weights. The protocol converts weights into fixed per-share quantities. From that point, the quantities — not the dollar figure — are the truth.

```solidity
qty[i] = (weight[i] * 1e18) / price[i]
```

### Three-Asset Creation Example

Three assets, equal weight:

| Asset | Weight | Price | Quantity per Share |
|-------|--------|-------|--------------------|
| BTC | 33.33% | $50,000 | 0.000006666 BTC |
| ETH | 33.33% | $3,000 | 0.000111100 ETH |
| SOL | 33.34% | $100 | 0.003334000 SOL |

At creation, NAV = $1.00. Each share represents exactly these quantities.

```solidity
NAV = (0.000006666 * 50000) + (0.000111100 * 3000) + (0.003334000 * 100)
    = 0.3333 + 0.3333 + 0.3334
    = $1.00
```

## DTF Key Invariants

Three rules that hold without exception:

<Note>
**Quantities only change on rebalance.** Buying and selling does not alter per-share quantities. Buy/sell mints or burns shares proportionally. The basket composition stays the same.
</Note>

1. **Buy/sell = mint/burn shares.** Buy $100 at NAV $1.05, receive ~95.24 shares. Per-share quantities do not move.
2. **NAV drifts from $1 over time.** Basket appreciates, NAV rises. Basket falls, NAV falls. That is the *point*.
3. **Quantities are stored on-chain.** The `_itpInventory` mapping in `IndexStorage.sol` is canonical. Everything else mirrors it.

## DTF Rebalancing

A rebalance changes per-share quantities to match new target weights while preserving NAV at the moment of rebalance. New composition, same share price.

### Rebalance Quantity Formula

```solidity
qty_new[i] = (w_new[i] * currentNAV) / price[i]
```

Where:
- `w_new[i]` is the new target weight for asset `i`
- `currentNAV` is the NAV at the moment of rebalance
- `price[i]` is the current price of asset `i`

### Rebalance Worked Example

Prices move: BTC to $60,000, ETH to $3,500, SOL to $120. NAV updates:

```solidity
NAV = (0.000006666 * 60000) + (0.000111100 * 3500) + (0.003334000 * 120)
    = 0.3999 + 0.3889 + 0.4001
    = $1.1889
```

The deployer sets new weights: BTC 50%, ETH 30%, SOL 20%.

| Asset | New Weight | Price | New Quantity |
|-------|-----------|-------|-------------|
| BTC | 50% | $60,000 | 0.000009908 |
| ETH | 30% | $3,500 | 0.000101906 |
| SOL | 20% | $120 | 0.001981500 |

Post-rebalance NAV check:

```solidity
NAV = (0.000009908 * 60000) + (0.000101906 * 3500) + (0.001981500 * 120)
    = 0.5945 + 0.3567 + 0.2378
    = $1.1890  (same as before, within rounding)
```

<Warning>
NAV is preserved across a rebalance. Exposure is not. You hold the same dollar value but a different bet going forward.
</Warning>

## DTF ERC-4626 Vault Tokens

Every DTF implements [ERC-4626](https://eips.ethereum.org/EIPS/eip-4626) (~2 min). Standard interface, full DeFi composability.

- **Fungible** — all shares of the same DTF are identical
- **Transferable** — send DTF tokens to any address
- **Collateralizable** — use as collateral in [lending markets](/index/concepts/lending) (~3 min)
- **18 decimals** — matching ERC-20 conventions

Where the formula lives in code:

### Implementation Reference

| Layer | Location | Function |
|-------|----------|----------|
| Contract | `Index.sol` | `createITP()` — computes initial quantities from weights and prices |
| Contract | `Index.sol` | `_getCurrentPrice()` — computes NAV from stored inventory |
| Contract | `Index.sol` | `updateWeights()` — rebalance: recalculates quantities preserving NAV |
| Storage | `IndexStorage.sol` | `_itpInventory[itpId]` — canonical per-share quantities |
| Oracle | `nav.rs` | `calculate_nav()` — reads inventory via `getITPState` |
| Frontend | `useItpNav.ts` | Inventory-first calculation, weight fallback for legacy DTFs |
