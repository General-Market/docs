# On-Chain Contract Architecture

7,300 lines of Solidity on the Index L3 (Arbitrum Orbit) plus a smaller surface on Settlement. UUPS proxies (Universal Upgradeable Proxy Standard from OpenZeppelin), BLS signature verification on every state-changing path. No test modes, no owner overrides.

Key terms used below:

- **DTF** — Dex Traded Fund. An on-chain ETF whose share token tracks a fixed inventory of underlying assets.
- **NAV** — Net Asset Value. Per-share value of a DTF.
- **BLS** — A pairing-based signature scheme; the aggregated signature of `ceil(2n/3)` oracle nodes authorises any state change.
- **UUPS proxy** — Upgrade pattern where the proxy address is permanent and only the implementation behind it changes.

## DTF Core Contracts

| Contract | Description |
|---|---|
| **Index.sol** | Central entry point for order submission, block/fill confirmation, and Dex Traded Fund (DTF) management. Houses `createITP` (converts weights to fixed per-share quantities), `_getCurrentPrice` (computes NAV from inventory), and `updateWeights` (rebalance that preserves NAV). |
| **ITP.sol** | ERC-4626 vault wrapping each DTF's share token. Handles minting on buy, burning on sell, and exposes standard vault accounting. |
| **BridgeProxy.sol** | Cross-chain order routing between Arbitrum L1/L2 and the L3. Relays user orders submitted on Arbitrum down to the Index contract on L3. |
| **BridgedItpFactory.sol** | Factory that creates ERC-20 representations of DTF shares on Arbitrum, enabling L1/L2 composability without requiring users to interact with L3 directly. |
| **Governance.sol** | Administrative controls including global pause, per-DTF pause, and role management. |
| **BLSCustody.sol** | Executes custody operations (deposits, withdrawals) gated by BLS-signed consensus from oracle nodes. |

## Registry Contracts

| Contract | Description |
|---|---|
| **OracleRegistry.sol** | Stores oracle node BLS public keys, manages the aggregated public key, and handles key rotation. New oracle nodes must register in OracleRegistry before participating in consensus. |
| **CollateralRegistry.sol** | Maintains the whitelist of accepted collateral tokens (currently USDC). Controls which tokens can back DTF creation and order settlement. |
| **AssetPairRegistry.sol** | Configures trading pairs available on the protocol -- maps asset identifiers to on-chain and off-chain parameters. |
| **FeeRegistry.sol** | Defines fee tiers for different operations and manages deployer fee claiming. Protocol fees are accrued in FeeRegistry and claimable by authorized addresses. |

## Shared Libraries

| Library | Purpose |
|---|---|
| **TypesLib.sol** | Shared struct definitions used across the protocol: `LimitOrder`, `Fill`, `ITP`, block metadata, and more. |
| **ErrorsLib.sol** | Custom error definitions ranging from `E001` through `E069+`. Every revert in the protocol uses a typed error from `ErrorsLib`. |
| **EventsLib.sol** | Event definitions emitted by core contracts -- `OrderSubmitted`, `BlockConfirmed`, `FillExecuted`, `ITPCreated`, `WeightsUpdated`, etc. |
| **BLSLib.sol** | BLS signature verification using EVM precompiles on the BN254 curve. Called by every path that validates oracle node consensus. |

## Storage Layout

<Info>
  `IndexStorage.sol` holds `_itpInventory[itpId]` — the fixed per-share quantities for each asset. Set at creation, changed only on rebalance. Buy and sell mint or burn shares proportionally and never touch inventory. This is the invariant the rest of the system depends on.
</Info>

All upgradeable contracts use UUPS proxies (OpenZeppelin 5.x). Storage slots survive upgrades. The proxy address is permanent; only the implementation changes.

## DTF NAV Pricing Model

A DTF starts at \$1. NAV drifts as the underlying assets move — that drift is the product.

```solidity
// At creation (or rebalance), weights become fixed quantities:
qty[i] = (weight[i] * 1e18) / price[i]

// NAV is always computed from quantities and current prices:
NAV = sum(qty[i] * price[i]) / 1e18
```

The four invariants:

- Per-share quantities live in `_itpInventory`. They change only on rebalance.
- Buy and sell mint or burn shares proportionally. They never touch quantities.
- Rebalance preserves NAV: `qty_new[i] = (w_new[i] * currentNAV) / price[i]`.
- NAV drifts from \$1 as underlying prices move. Drift is the product, not a bug.

## BLS Signature Security

Every state-changing call verifies an aggregated BLS signature against the public key stored in `OracleRegistry.sol`. There is no fallback path.

<Warning>
  BLS verification is **never bypassed**. No test modes, no `onlyOwner` override, no `aggregatedPubkey.length == 0` short-circuit. If BLS is blocking development, fix the BLS pipeline — generate proper test keys, register them, compute valid signatures.
</Warning>

| Property | Value |
|---|---|
| Curve | BN254 (alt_bn128) |
| Precompiles | `0x06` (add), `0x07` (mul), `0x08` (pairing) |
| Threshold | `ceil(2n/3)` of registered oracle nodes |
| Key storage | Aggregated public key in `OracleRegistry.sol`, updated on join/leave/rotation |
| Verification site | `BLSLib.verify(message, signature, aggregatedPubkey)` in `confirmBlock()` |

## Vision Prediction Market Contracts

Vision is a parimutuel prediction market on L3. Users stake USDC on outcomes; winners split the pool proportional to their stake.

| Contract | Description |
|---|---|
| **Vision.sol** | Parimutuel prediction market contract. Manages block creation, bet placement, outcome resolution, and payout distribution. Each block defines a set of outcomes; users deposit USDC to back a chosen outcome, and winning bettors split the total pool proportionally. |
| **BotRegistry.sol** | Manages automated bot registration for Vision. Bots register with a wallet address and can participate in Vision blocks programmatically. BotRegistry tracks bot metadata and enforces registration requirements. |
