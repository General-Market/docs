---
title: "Backtesting"
description: "Simulate portfolio performance with historical data before deploying a DTF"
---

Simulate a basket strategy against historical data, then deploy the result as a live Dex Traded Fund (DTF — a tokenized basket of crypto assets, like an on-chain ETF). ~5 min for one run, ~15 min for a sweep.

**Prereqs:**
- A category in mind (Layer 1s, DeFi, AI, Memecoins, etc.)
- A weighting scheme (equal, market cap, momentum — full list below)
- A rebalance cadence (days, or a drift threshold)

**What you get:** total return, Sharpe ratio, max drawdown, NAV chart, final holdings — plus a one-click Deploy button.

<Warning>
**Past performance does not guarantee future results.** Backtesting cannot account for future market conditions, liquidity changes, or black swan events. Read [Risks](/index/guides/risks) before committing capital.
</Warning>

## Backtesting via the UI

Open the **Backtest** section. Three steps to a result.

<Steps>
  <Step title="Step 1: Select a category">
    Pick an asset category. Layer 1s, DeFi Blue Chips, AI Tokens, Memecoins, Made in China — 50+ available from CoinGecko and DefiLlama.

    Eligibility: only coins listed on Bitget at some point. Untradeable assets are excluded by design.
  </Step>

  <Step title="Step 2: Configure parameters">
    Set five values. Defaults work for a first pass.

    | Parameter | What it does | Example |
    |-----------|-------------|---------|
    | **Top N** | Number of assets by market cap | `10` |
    | **Weighting** | Allocation scheme (table below) | `mcap` |
    | **Rebalance** | Days between rebalances | `30` |
    | **Fee** | Simulated trading fee per rebalance | `0.1%` |
    | **Spread** | Slippage multiplier | `1.0` |
  </Step>

  <Step title="Step 3: Run and review">
    Click **Run Backtest**. ~3 sec for a cached config, ~10–30 sec for a fresh run.

    Output: total return, Sharpe ratio, max drawdown, annualized return, NAV chart, final holdings.

    Next step: open the [Sweep section](#sweep-mode) to compare configurations, or jump to [Deploy as DTF](#deploy-as-dtf).
  </Step>
</Steps>

## Backtesting via the API

All simulation endpoints are **GET** requests with query parameters. No authentication required. Data is public.

**Base URL:** `https://generalmarket.io/api`

### Run a single backtest

<CodeGroup>

```bash cURL
curl "https://generalmarket.io/api/sim/run?\
category_id=layer-1&\
top_n=10&\
weighting=mcap&\
rebalance_days=30&\
base_fee_pct=0.1&\
spread_multiplier=1.0"
```

```python Python
import requests

resp = requests.get("https://generalmarket.io/api/sim/run", params={
    "category_id": "layer-1",
    "top_n": 10,
    "weighting": "mcap",
    "rebalance_days": 30,
    "base_fee_pct": 0.1,
    "spread_multiplier": 1.0,
})
result = resp.json()

print(f"Return: {result['stats']['total_return_pct']:.1f}%")
print(f"Sharpe: {result['stats']['sharpe_ratio']:.2f}")
print(f"Max DD: {result['stats']['max_drawdown_pct']:.1f}%")
print(f"Run ID: {result['run_id']} (use for holdings lookup)")
```

### Query parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `category_id` | string | Yes | — | Category slug (from `/sim/categories`) |
| `top_n` | int | Yes | — | Number of top assets by market cap |
| `weighting` | string | Yes | — | Weighting scheme (see table below) |
| `rebalance_days` | int | Yes | — | Days between rebalances |
| `base_fee_pct` | float | No | `0.1` | Fee % per rebalance |
| `spread_multiplier` | float | No | `1.0` | Slippage multiplier |
| `start_date` | string | No | `2020-01-01` | ISO date (YYYY-MM-DD) |
| `force` | bool | No | `false` | Skip cache, force recompute |
| `threshold_pct` | float | No | — | Drift-based rebalance threshold (%) |
| `fng_mode` | string | No | — | Fear & Greed regime: `fear`, `greed`, or `both` |
| `fng_fear_threshold` | int | No | `25` | FNG index below this = fear |
| `fng_greed_threshold` | int | No | `75` | FNG index above this = greed |
| `fng_cash_pct` | float | No | `0.4` | % to move to stables during greed |
| `dom_mode` | string | No | — | Dominance regime: `btc`, `eth`, or `inverse` |
| `dom_lookback` | int | No | `30` | Lookback days for dominance trend |
| `vc_mode` | string | No | — | VC filter mode |
| `vc_investors` | string | No | — | Comma-separated investor names |
| `vc_min_amount_m` | float | No | — | Min funding round in $M |
| `vc_round_types` | string | No | — | Comma-separated round types |

## Weighting Strategies

| Weighting | Query Value | Description |
|-----------|-------------|-------------|
| Equal | `equal` | 1/N allocation across all assets |
| Market Cap | `mcap` | Proportional to market cap |
| Capped Market Cap | `capped_mcap_10` | Market cap with 10% single-asset cap |
| Square Root Market Cap | `sqrt_mcap` | Dampened market cap weighting |
| Momentum | `momentum_90` | Top by 90-day momentum score |
| Inverse Volatility | `invvol_60` | Lower volatility = higher weight |
| Dual Momentum | `dual_mom_180` | Combined momentum/volatility signal |
| Risk Parity | `risk_parity_60` | Equal risk contribution per asset |
| Min Variance | `min_var_60` | Minimize portfolio variance |
| Multi-Factor | `multi_factor_90` | Composite momentum + vol + mcap |
| Low Volatility | `low_vol_60` | Over-weight low-vol assets |

**DeFi-only strategies** (for `dl-*` categories):

| Weighting | Query Value | Description |
|-----------|-------------|-------------|
| TVL Weight | `tvl` | Proportional to Total Value Locked |
| TVL Capped | `tvl_capped_10` | TVL with 10% cap |
| TVL Sqrt | `tvl_sqrt` | Dampened TVL |
| Fees Weight | `fees` | Weight by protocol fee revenue |
| Revenue Weight | `revenue` | Weight by protocol revenue |
| Volume Weight | `volume` | Weight by trading volume |
| TVL Momentum | `tvl_momentum_90` | TVL trend-following |
| Fee Efficiency | `fee_efficiency` | Fees-to-TVL ratio |
| Yield Weight | `yield` | Weight by yield |

## Sweep Mode

Sweep mode varies one parameter across many values and streams results for each variant. Use it to scan a parameter space in a single call.

**Sweep dimensions:** `top_n`, `weighting`, `rebalance`, `category`, `threshold`

<CodeGroup>

```bash cURL — sweep top_n
curl -N "https://generalmarket.io/api/sim/sweep-stream?\
sweep=top_n&\
category_id=layer-1&\
weighting=mcap&\
rebalance_days=30"
```

```bash cURL — sweep weighting strategies
curl -N "https://generalmarket.io/api/sim/sweep-stream?\
sweep=weighting&\
category_id=layer-1&\
top_n=10&\
rebalance_days=30"
```

```python Python — sweep top_n with SSE
import requests

resp = requests.get(
    "https://generalmarket.io/api/sim/sweep-stream",
    params={
        "sweep": "top_n",
        "category_id": "layer-1",
        "weighting": "mcap",
        "rebalance_days": 30,
    },
    stream=True,
)

for line in resp.iter_lines():
    if line and line.startswith(b"data: "):
        import json
        event = json.loads(line[6:])
        if event["type"] == "result":
            s = event["stats"]
            print(f"top_{event['config']['top_n']:>3d}  "
                  f"return={s['total_return_pct']:>8.1f}%  "
                  f"sharpe={s['sharpe_ratio']:.2f}  "
                  f"drawdown={s['max_drawdown_pct']:.1f}%")
```

| Sweep | What It Varies | Values |
|-------|---------------|--------|
| `top_n` | Number of holdings | 5, 10, 20, 30, 50, 100, 200 |
| `weighting` | All weighting schemes | equal, mcap, momentum, invvol, etc. |
| `rebalance` | Rebalance frequency | 14d, 30d, 60d, 90d, 180d + drift bands (3%, 5%, 10%, 15%) |
| `category` | Multiple categories | Pass `categories=layer-1,defi,ai` |
| `threshold` | Drift rebalance bands | 3%, 5%, 10%, 15%, 20% |

<Tip>
One call tests all variants. Results stream as they complete. Avoid cherry-picking the highest-return variant — ask why it performed best and whether that reason will hold out of sample.
</Tip>

## Fetch Holdings from a Backtest

After running a backtest, fetch the final portfolio composition by `run_id`.

<CodeGroup>

```bash cURL
curl "https://generalmarket.io/api/sim/holdings?run_id=4821"
```

```python Python
resp = requests.get("https://generalmarket.io/api/sim/holdings", params={"run_id": 4821})
holdings = resp.json()["holdings"]
for h in holdings:
    print(f"{h['symbol']:>6s}  {h['weight_pct']:.1f}%")
```

</CodeGroup>

Pass an optional `date` parameter (YYYY-MM-DD) to get holdings at a specific rebalance date.

## Market Signal Integrations

Layer additional signals onto any backtest. Three are supported.

### Fear & Greed Index (FNG)

Shift allocation between crypto and stablecoins based on the FNG index (0 = extreme fear, 100 = extreme greed).

```bash
curl "https://generalmarket.io/api/sim/run?\
category_id=layer-1&top_n=10&weighting=mcap&rebalance_days=30&\
fng_mode=both&fng_fear_threshold=25&fng_greed_threshold=75&fng_cash_pct=0.4"
```

**Behavior:**
- FNG > 75 (greed) → 40% of portfolio moves to stables.
- FNG < 25 (fear) → fully deployed in crypto.
- Between thresholds → no change.

### BTC/ETH Dominance

Adjust crypto allocation based on Bitcoin or Ethereum market-cap dominance trends.

```bash
curl "https://generalmarket.io/api/sim/run?\
category_id=layer-1&top_n=10&weighting=mcap&rebalance_days=30&\
dom_mode=btc&dom_lookback=30"
```

### VC Funding Filter

Filter the eligible universe by venture-capital backing — specific investors, minimum round size, or round types.

```bash
curl "https://generalmarket.io/api/sim/run?\
category_id=layer-1&top_n=10&weighting=mcap&rebalance_days=30&\
vc_mode=include&vc_investors=a16z,paradigm&vc_min_amount_m=10"
```

## Understanding Results

Seven metrics, one NAV series. Read them together.

### Key metrics

| Metric | What it tells you |
|--------|-------------------|
| **Total Return %** | Cumulative gain/loss over the full period |
| **Annualized Return** | Return normalized to a yearly rate |
| **Max Drawdown %** | Largest peak-to-trough decline — worst-case pain |
| **Sharpe Ratio** | Risk-adjusted return. >1.0 is decent, >2.0 is strong |
| **Total Fees %** | Cumulative fees paid across all rebalances |
| **Total Trades** | Number of individual asset trades executed |
| **Total Delistings** | Assets removed mid-backtest (delisted from exchange) |

### What the NAV series represents

NAV (Net Asset Value) = portfolio value per share. The `nav_series` starts at `1.0` and tracks portfolio value over time. A NAV of `3.12` means 212% return from the start date.

## Deploy as DTF

Turn a backtest into a live DTF in three clicks. ~2 min including wallet confirmation.

<Steps>
  <Step title="Step 1: Review final holdings">
    Open the holdings table from the backtest results. Confirm the weights match your thesis before going on-chain.
  </Step>

  <Step title="Step 2: Click Deploy Index">
    The button pre-fills the DTF creation form with the backtested assets and weights from the final rebalance.
  </Step>

  <Step title="Step 3: Confirm on-chain">
    Add a name and description. Confirm the transaction in your wallet. ~30 sec to confirm.

    Result: the DTF is live on the **Markets** page. Buyers can trade it immediately. See [Create a DTF](/index/guides/create-itp) for the full creation flow.
  </Step>
</Steps>

<Warning>
The deployed DTF uses the weights from the final rebalance. It does **not** auto-rebalance. You must trigger every rebalance manually — see [Rebalancing](/index/guides/rebalancing).
</Warning>

## Checklist: Running an Honest Backtest

Seven habits. Apply each before treating a result as conclusive.

<Steps>
  <Step title="Step 1: Pick a category that matches your thesis">
    Do not backtest "all crypto" for a DeFi strategy. Use the narrowest category that still contains your universe.
  </Step>

  <Step title="Step 2: Start with equal weight">
    Equal weight is the null hypothesis. If a market-cap or momentum scheme cannot beat equal-weight, the added complexity earned nothing.
  </Step>

  <Step title="Step 3: Use realistic fees">
    Default fee is 0.1%. For illiquid altcoins, set `spread_multiplier` to 2.0 or higher. Default fees are the most common source of inflated backtest returns.
  </Step>

  <Step title="Step 4: Run a sweep before committing">
    Use `sweep=top_n` and `sweep=weighting` to map the parameter space. Treat any single best-performing config with suspicion until a sweep confirms it.
  </Step>

  <Step title="Step 5: Check drawdown, not just return">
    A 500% return with -90% max drawdown means a 90% loss was lived through. Drawdown is the metric you would have felt in real time.
  </Step>

  <Step title="Step 6: Look at delistings">
    High `total_delistings` means the category contains flaky assets. The backtest handles delistings cleanly; live trading does not.
  </Step>

  <Step title="Step 7: Compare against BTC">
    If your strategy cannot beat BTC on a risk-adjusted basis (Sharpe ratio), the complexity adds nothing. BTC is the benchmark.

    Next: [Deploy as DTF](#deploy-as-dtf) or read [Risks](/index/guides/risks).
  </Step>
</Steps>
