A block groups multiple markets into one prediction game. Every tick, all markets resolve at once.

- **Join:** deposit USDC, commit a bitmap hash, set `stakePerTick`
- **Tick duration:** 1 second to 30 days
- **Min stake:** 0.1 USDC per tick (100,000 in 6-decimal USDC)
- **States:** Created → Running → Paused (optional) → Running
- **Pausing requires BLS consensus** — 2/3+ of registered oracles must sign

## Quick Start: Join a Block

Fetch active blocks and join one with a USDC deposit:

```bash
# 1. List active blocks
curl https://generalmarket.io/api/vision/blocks

# 2. Join on-chain (Solidity)
vision.joinBlock(blockId, depositAmount, stakePerTick, bitmapHash)
```

## What Is a Block?

A block groups multiple markets (e.g., BTC-USD, ETH-USD, SOL-USD) into one prediction game. Every tick, all markets resolve simultaneously. Players win or lose based on how many markets they predicted correctly.

You pick UP or DOWN for each market. Your payout depends on how your picks compare to other players' picks across all markets — the parimutuel pot pays winners from losers' stakes.

## Creating a Block

Anyone can create a block. Call `createBlock`. You choose the markets, the resolution types, and the tick duration:

```solidity
function createBlock(
    bytes32[] calldata marketIds,
    uint8[] calldata resolutionTypes,
    uint256 tickDuration,
    uint256[] calldata customThresholds
) external returns (uint256 blockId);
```

**Example:** Create a block with 3 crypto markets, 10-minute ticks, using basic UP/DOWN resolution:

```javascript
const marketIds = [
  keccak256(toUtf8Bytes("BTC-USD")),
  keccak256(toUtf8Bytes("ETH-USD")),
  keccak256(toUtf8Bytes("SOL-USD")),
];

const resolutionTypes = [0, 0, 0]; // UP_0 for all markets
const tickDuration = 600;          // 10 minutes
const customThresholds = [];       // Not needed for UP_0

const tx = await vision.createBlock(
  marketIds, resolutionTypes, tickDuration, customThresholds
);
```

<Info>
`marketIds` and `resolutionTypes` must be the same length. If they differ, the transaction reverts with `ArrayLengthMismatch`.
</Info>

## Tick Duration Options

`tickDuration` sets how often the block resolves. Common configurations:

| Duration | Use Case |
|----------|----------|
| 60s (1 min) | High-frequency trading games |
| 600s (10 min) | Standard prediction rounds |
| 3600s (1 hour) | Hourly market predictions |
| 86400s (1 day) | Daily market predictions |
| 604800s (1 week) | Weekly outlook predictions |

<Warning>
`tickDuration` must be greater than 0 and at most `MAX_TICK_DURATION` (30 days = 2,592,000 seconds). Passing 0 or exceeding the maximum reverts with `InvalidTickDuration`.
</Warning>

## Block States

A block moves through four states:

```
Created --> Running --> Paused (optional) --> Running
```

1. **Created**: registered on-chain. Players can join immediately.
2. **Running**: ticks resolve every `tickDuration`. Players can join, deposit, update bitmaps, claim rewards.
3. **Paused**: oracles paused the block via BLS consensus (e.g., unreliable price feed). No new joins. Existing positions remain.
4. **Unpaused**: oracles resumed via BLS consensus. Normal operation.

<Info>
Pausing and unpausing require BLS signatures from 2/3+ of registered oracles. This prevents any single party from disrupting a block.
</Info>

## Updating Markets

A block creator can change which markets are included, but not unilaterally. Changes require BLS oracle consensus:

```solidity
function updateBlockMarkets(
    uint256 blockId,
    bytes32[] calldata marketIds,
    uint8[] calldata resolutionTypes,
    bytes calldata blsSig
) external;
```

The BLS signature must cover the block ID, new market IDs, new resolution types, and the current tick number. This ensures oracles have reviewed and approved the change.

## Joining a Block

Players deposit USDC and commit a bitmap hash in one call:

```solidity
function joinBlock(
    uint256 blockId,
    uint256 depositAmount,    // Initial USDC deposit
    uint256 stakePerTick,     // Amount risked per tick per market
    bytes32 bitmapHash        // keccak256 of the player's bitmap
) external;
```

<Tip>
`stakePerTick` must be at least `MIN_STAKE_PER_TICK` (0.1 USDC = 100,000 in 6-decimal USDC). The initial deposit must be at least equal to `stakePerTick`.
</Tip>

See [Bitmaps](/docs/blocks/concepts/bitmaps) for how to construct and commit predictions.

## Technical Details

### Block Struct

On-chain, a block is stored as this struct:

```solidity
struct Block {
    address creator;           // Wallet that created the block
    bytes32[] marketIds;       // keccak256 hashes of asset IDs (e.g., keccak256("BTC-USD"))
    uint8[] resolutionTypes;   // How each market is resolved (see Resolution Types)
    uint256 tickDuration;      // Seconds between resolutions
    uint256[] customThresholds; // Custom thresholds in basis points (for _X types)
    uint256 createdAtTick;     // block.timestamp / tickDuration at creation
    bool paused;               // Whether the block is currently paused
}
```

| Field | Description |
|-------|-------------|
| `creator` | The address that called `createBlock`. Only the creator can set metadata and update markets. |
| `marketIds` | Array of `bytes32` market identifiers. Each is `keccak256(assetId)` where `assetId` is a UTF-8 string like `"BTC-USD"`. |
| `resolutionTypes` | Parallel array to `marketIds`. Each entry is a `uint8` from the `ResolutionType` enum (0-7). See [Resolution Types](/docs/blocks/concepts/resolution-types). |
| `tickDuration` | How often the block resolves, in seconds. Must be between 1 second and 30 days (`MAX_TICK_DURATION`). |
| `customThresholds` | Parallel array for resolution types that use custom thresholds (`UP_X`, `DOWN_X`, `FLAT_X`). Values are in basis points. |
| `createdAtTick` | The tick number when the block was created, computed as `block.timestamp / tickDuration`. |
| `paused` | When `true`, no new players can join. Requires a BLS-signed oracle consensus to pause or unpause. |

### Block Metadata

Block creators can attach metadata — name, description, image — to make their block discoverable:

```solidity
function setBlockMetadata(
    uint256 blockId,
    string calldata name,          // max 64 bytes
    string calldata description,   // max 280 bytes
    string calldata websiteUrl,    // max 128 bytes
    string calldata videoUrl,      // max 256 bytes
    string calldata imageUrl       // max 256 bytes
) external;
```

Only the block creator can set metadata. Exceeding any string length limit reverts with `StringTooLong`.

Creators can also set a display name for themselves:

```solidity
function setDeployerName(string calldata name) external; // max 64 bytes
```
