Two of three oracles must sign your balance before the contract pays out. That signature is a BLS (Boneh-Lynn-Shacham) threshold signature — multiple partial signatures aggregated into one proof.

- Off-chain: oracles compute your balance from tick results, sign it
- On-chain: you submit the aggregated signature, the contract verifies and pays
- Fee: 0.05% on profits only, applied at claim or withdrawal
- Guards: no double-claim, no out-of-range ticks, no insolvent payout
- BLS verification is never bypassed — not in dev, not in tests

## Quick Start: Check Your Balance

```bash
curl https://generalmarket.io/api/vision/balance/{blockId}/{playerAddress}
```

Response: `{ "block_id": 1, "player": "0x...", "balance": "15000000", "stake_per_tick": "100000" }`

To claim on-chain, you need BLS-signed proofs from 2/3+ oracles. See [Bot Development](/docs/blocks/bots/development) for the full claim flow.

## Why Off-Chain Balance Tracking?

Resolving every tick on-chain for every player would cost more in gas than the stakes themselves. Vision splits the work:

- **On-chain**: deposits, withdrawals, bitmap commitments, BLS-verified claims
- **Off-chain**: tick resolution, bitmap reveals, balance computation, BLS signing

The contract does not store per-tick balances. It accepts whatever number 2/3+ of registered oracles sign — the BLS threshold is the source of truth.

## BLS Signature Flow

The balance proof lifecycle has 5 steps: request, compute, sign, aggregate, verify.

### Step 1: Player Requests Balance Proof

The player queries an oracle node for their current balance:

```bash
GET /vision/balance/{blockId}/{playerAddress}
```

**Response:**

```json
{
  "block_id": 1,
  "player": "0xAbC...123",
  "balance": "15000000",
  "stake_per_tick": "100000"
}
```

<Info>
In the full implementation, each oracle returns a partial BLS signature. The player collects signatures from multiple oracles to aggregate.
</Info>

### Step 2: Oracles Compute Balance

Each oracle independently computes your balance:

1. Tracks all tick results since the player's last claim.
2. Sums deposits + winnings - losses - fees.
3. Arrives at the player's `newBalance`.

All oracles run the same deterministic resolution logic on the same price feeds and bitmaps. Agreement means consensus. Disagreement means a bug — investigate.

### Step 3: Oracles BLS-Sign the Balance

Each oracle signs this message. The signature is the oracle's cryptographic attestation that the computed balance is correct:

```solidity
bytes32 message = keccak256(abi.encode(
    chainId,            // Chain ID (prevents cross-chain replay)
    contractAddress,    // Vision contract address
    "CLAIM",            // Action tag
    blockId,            // Block ID
    playerAddress,      // Player's address
    fromTick,           // First tick in the claim range
    toTick,             // Last tick in the claim range
    newBalance          // Computed balance after all ticks
));
```

The player collects BLS partial signatures from at least 2/3 of registered oracles.

### Step 4: Player Aggregates and Submits

The player aggregates the partial BLS signatures into a single signature and submits it on-chain:

```solidity
function claimRewards(
    uint256 blockId,
    uint256 fromTick,
    uint256 toTick,
    uint256 newBalance,
    bytes calldata blsSignature  // Aggregated BLS signature
) external;
```

### Step 5: Contract Verifies and Pays

The contract verifies the signature and either pays or rejects:

1. Reconstructs the message hash from the submitted parameters.
2. Verifies the aggregated BLS signature against the oracle registry's aggregated public key.
3. If valid:
   - Compares `newBalance` to `oldBalance`.
   - If `newBalance > oldBalance`: computes winnings, deducts the 0.05% fee, transfers the payout.
   - If `newBalance <= oldBalance`: records the loss, no payout.
4. Updates `position.lastClaimedTick = toTick`.

```solidity
if (newBalance > oldBalance) {
    uint256 winnings = newBalance - oldBalance;
    uint256 fee = (winnings * PROTOCOL_FEE_BPS) / BPS_DENOMINATOR;
    accumulatedFees += fee;
    uint256 payout = winnings - fee;
    USDC.safeTransfer(msg.sender, payout);
}
```

<Warning>
BLS verification is never bypassed. Not in local development, not in tests, not anywhere. If BLS verification blocks your workflow, fix the BLS pipeline — do not add bypass flags.
</Warning>

## Claiming vs. Withdrawing

Two exit paths. `claimRewards` takes winnings and keeps your position open. `withdraw` takes everything and closes it. Both require a BLS proof.

| Action | Keeps position? | Fee basis | BLS action tag |
|---|---|---|---|
| `claimRewards` | Yes | winnings since last claim | `"CLAIM"` |
| `withdraw` | No | total profit since first deposit | `"WITHDRAW"` |
| `forceWithdraw` | No (oracle-initiated) | total profit | `"FORCE_WITHDRAW"` |

### Claiming (Partial)

`claimRewards` lets a player claim accumulated winnings while staying in the block:

```solidity
claimRewards(blockId, fromTick, toTick, newBalance, blsSig)
```

- Pays out the difference between old and new balance (minus fees).
- The player remains in the block and continues playing.
- `lastClaimedTick` is updated to prevent double-claims.

### Withdrawing (Full Exit)

`withdraw` removes the player from the block entirely:

```solidity
function withdraw(
    uint256 blockId,
    uint256 finalBalance,
    bytes calldata blsSignature
) external;
```

The BLS message for withdrawal uses the `"WITHDRAW"` action tag:

```solidity
bytes32 message = keccak256(abi.encode(
    chainId, contractAddress, "WITHDRAW",
    blockId, playerAddress, finalBalance
));
```

On withdrawal:
- Fees are calculated on **total profit** (finalBalance - totalDeposited), not just the last claim.
- The player's position is deleted from storage.
- All remaining USDC is transferred to the player.

### Force Withdraw

Oracles can force-withdraw a player via BLS consensus. Used when a position must be closed by the protocol — final and cryptographically verified:

```solidity
function forceWithdraw(
    uint256 blockId,
    address player,
    uint256 finalBalance,
    bytes calldata blsSignature
) external;
```

The BLS message uses the `"FORCE_WITHDRAW"` action tag. This is an oracle-level operation that requires consensus.

## Claim Guards

The contract enforces these safety checks. Each one reverts with a specific error:

| Check | Error | Description |
|-------|-------|-------------|
| Player must have joined | `NotJoined` | `stakePerTick == 0` means not in block |
| No double-claiming | `TickAlreadyClaimed` | `fromTick` must be after `lastClaimedTick` |
| Valid tick range | `InvalidTickRange` | `toTick >= fromTick` |
| BLS signature valid | `InvalidBLSSignature` | Aggregated signature must verify |
| Solvency | `InsolventPayout` | Contract must hold enough USDC |

## Code Example: Requesting a Proof

A complete example — request a balance proof from oracles, aggregate signatures, submit the claim on-chain:

```typescript
import { ethers } from "ethers";

const VISION_ABI = [
  "function claimRewards(uint256 blockId, uint256 fromTick, uint256 toTick, uint256 newBalance, bytes blsSignature)",
  "function getPosition(uint256 blockId, address player) view returns (tuple(bytes32 bitmapHash, uint256 stakePerTick, uint256 startTick, uint256 balance, uint256 lastClaimedTick, uint256 joinTimestamp, uint256 totalDeposited, uint256 totalClaimed))",
];

async function claimRewards(
  visionContract: ethers.Contract,
  blockId: number,
  oracleUrls: string[],
  playerAddress: string
) {
  // 1. Get current position
  const position = await visionContract.getPosition(blockId, playerAddress);
  const lastClaimed = position.lastClaimedTick.toNumber();

  // 2. Request balance proof from oracles
  const proofs = await Promise.all(
    oracleUrls.map(async (url) => {
      const resp = await fetch(`${url}/vision/balance/${blockId}/${playerAddress}`);
      return resp.json();
    })
  );

  // 3. Verify oracles agree on balance
  const balances = proofs.map((p) => p.balance);
  const agreed = balances.every((b) => b === balances[0]);
  if (!agreed) throw new Error("Oracles disagree on balance");

  // 4. Aggregate BLS signatures (simplified)
  const aggregatedSig = aggregateBLSSignatures(proofs.map((p) => p.bls_signature));

  // 5. Submit claim on-chain
  const fromTick = lastClaimed > 0 ? lastClaimed + 1 : position.startTick.toNumber();
  const toTick = proofs[0].to_tick;
  const newBalance = proofs[0].balance;

  const tx = await visionContract.claimRewards(
    blockId, fromTick, toTick, newBalance, aggregatedSig
  );
  await tx.wait();

  console.log(`Claimed rewards for ticks ${fromTick}-${toTick}`);
}
```

</Tip>
