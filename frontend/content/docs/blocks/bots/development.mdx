# Bot Development

The Vision Bot Python framework (`vision-bot/`) handles RPC calls, bitmap encoding, and position tracking. You write one method: `predict(markets) -> list["UP" | "DOWN"]`.

The framework has four modules:

- **Core** — bitmap encoding, `Strategy` ABC, `RiskCheck`.
- **Chain** — `Executor` for on-chain reads/writes, oracle discovery, bitmap submission.
- **Feed** — WebSocket price feed with HTTP fallback.
- **Tracker** — position lifecycle, auto-claim, auto-withdraw, PnL persistence.

Each module is one file in `vision-bot/framework/`.

## Framework Architecture

```
    +-------------------------------------------------------------------+
    |                         VISION BOT (bot.py)                       |
    |                                                                   |
    |   +----------+     +----------+     +-----------+                 |
    |   |          |     |          |     |           |                 |
    |   |   Feed   +---->+   Core   +---->+   Chain   |                 |
    |   | (feed.py)|     |(core.py) |     |(chain.py) |                 |
    |   |          |     |          |     |           |                 |
    |   +----+-----+     +----+-----+     +-----+-----+                 |
    |        |                |                 |                       |
    |        |  WebSocket     |  Bitmap         |  On-chain             |
    |        |  prices        |  encoding       |  transactions         |
    |        |                |  + hashing      |  + oracle API         |
    |        |                |                 |                       |
    |        |           +----+------+    +-----+-------+              |
    |        |           |           |    |             |              |
    |        |           | Strategy  |    |   Tracker   |              |
    |        |           | (yours!)  |    |(tracker.py) |              |
    |        |           |           |    |             |              |
    |        |           +-----------+    +-----+-------+              |
    |        |                                  |                       |
    |        |                                  |  PnL file             |
    |        v                                  v  (pnl.json)           |
    |   +---------+                        +---------+                  |
    |   |data-node|                        |L3 chain |                  |
    |   |   WS    |                        | (RPC)   |                  |
    |   +---------+                        +---------+                  |
    +-------------------------------------------------------------------+
```

Four modules, one responsibility each:

| Module | File | Role |
|--------|------|------|
| **Core** | `framework/core.py` | Bitmap encoding, `Strategy` ABC, `RiskCheck`, config loading |
| **Chain** | `framework/chain.py` | `Executor` (all on-chain reads/writes), oracle discovery, bitmap submission |
| **Feed** | `framework/feed.py` | WebSocket price feed with HTTP fallback, history caching |
| **Tracker** | `framework/tracker.py` | Position lifecycle, auto-claim, auto-withdraw, PnL persistence |

## Core Components

### core.py — Primitives and Strategy ABC

The core module exposes three things: bitmap helpers, the `Strategy` base class, and `RiskCheck`.

**Bitmap encoding** converts a list of `"UP"` / `"DOWN"` strings into packed bytes. One prediction = one bit. 1 = UP, 0 = DOWN. Big-endian within each byte:

```python
from framework.core import encode_bitmap, hash_bitmap

bets = ["UP", "DOWN", "UP", "UP", "DOWN"]
bitmap = encode_bitmap(bets, count=5)   # b'\xb0' (10110 000)
bm_hash = hash_bitmap(bitmap)           # keccak256(bitmap) -> bytes32
```

```
  Bit layout (big-endian):
  +---+---+---+---+---+---+---+---+
  | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |   byte index 0
  +---+---+---+---+---+---+---+---+
  |UP |DN |UP |UP |DN | 0 | 0 | 0 |   (padding zeros for 5 markets)
  | 1 | 0 | 1 | 1 | 0 | 0 | 0 | 0 |   = 0xB0
  +---+---+---+---+---+---+---+---+
```

**Strategy ABC** — every strategy subclasses `Strategy` and implements `predict()`. One method, list in, list out:

```python
from framework.core import Strategy

class MyStrategy(Strategy):
    name = "my-strategy"  # matches config.toml strategy field

    def predict(self, markets: list[dict]) -> list[str]:
        # markets[i] = {"id": str, "price": float,
        #                "change": float|None, "volume": float|None,
        #                "market_cap": float|None}
        return ["UP" if m["price"] > 100 else "DOWN" for m in markets]
```

**RiskCheck** enforces two limits: maximum concurrent blocks and maximum total USDC exposure.

```python
from framework.core import RiskCheck

risk = RiskCheck(max_blocks=10, max_exposure=500 * 10**18)
risk.can_join(deposit=50 * 10**18)   # True if under limits
risk.record_join(block_id=1, deposit=50 * 10**18)
risk.record_exit(block_id=1)
```

### chain.py — Executor and On-Chain Interaction

`Executor` wraps every contract call behind one interface. One wallet, two contracts — Vision and USDC.

```
    Executor
    +---------------------------------------------------+
    |                                                   |
    |  READ methods:             WRITE methods:         |
    |  .usdc_balance()           .approve_usdc()        |
    |  .get_position()           .deposit_balance()     |
    |  .get_block_info()         .join_block()           |
    |  .next_block_id()          .register_bot()        |
    |  .vision_balance()         .claim_rewards()       |
    |                            .withdraw()            |
    |                            .update_bitmap()       |
    |                            .deposit_more()        |
    |                                                   |
    +---------------------------------------------------+
            |                           |
            v                           v
    +---------------+          +------------------+
    | Vision.sol    |          | L3_WUSDC (ERC20) |
    | (L3 chain)    |          | (18 decimals)    |
    +---------------+          +------------------+
```

<Warning>
Exception worth stating out loud: Vision runs on L3 where **USDC uses 18 decimals**, not 6. A 10 USDC deposit is `10 * 10**18`, not `10 * 10**6`. The framework sets `DECIMALS = 18`. Get the scaling wrong and you deposit dust — twelve orders of magnitude off.
</Warning>

Key chain functions beyond the Executor:

| Function | Purpose |
|----------|---------|
| `fetch_blocks(api_url)` | Get active blocks (oracle API -> vision-blocks.json fallback -> on-chain scan) |
| `fetch_block_config(data_node_url, config_hash)` | Fetch market list for a block from the data-node |
| `fetch_markets(data_node_url, market_ids)` | Get price snapshots for specific markets |
| `submit_bitmap(oracle_urls, player, block_id, bitmap, bitmap_hash)` | POST bitmap to all oracles with retry |
| `discover_oracles(mode, static_urls, w3)` | Resolve oracle endpoints (static list or on-chain registry) |

### feed.py — Real-Time Price Feed

`VisionFeed` keeps a background WebSocket open to the data-node for live prices. It auto-reconnects with exponential backoff (1s → 30s max) and falls back to HTTP when the socket is down.

```
    +------------------+       WebSocket        +------------+
    |   VisionFeed     | <--------------------> | data-node  |
    |                  |   {"subscribe":["1"]}  | /vision/ws |
    |  .subscribe()    | <-- price messages ---  |            |
    |  .prices("1")    |                        +------+-----+
    |  .history("1",   |       HTTP fallback           |
    |     "bitcoin")   | ---GET /vision/block/1/----> |
    |  .unsubscribe()  |        history?days=7         |
    |  .close()        |                               |
    +------------------+                               |
          |                                            |
          |  Background thread                         |
          |  _listen_loop()                            |
          |  - auto-reconnect                          |
          |  - exponential backoff (1s -> 30s max)     |
          |  - re-subscribes on reconnect              |
          +--------------------------------------------+
```

Usage in the bot:

```python
feed = VisionFeed(
    ws_url="ws://localhost:8200/vision/ws",
    http_url="http://localhost:8200",
)
feed.subscribe(["1", "3"], history_days=7)

# In the loop:
prices = feed.prices("1")
# {"bitcoin": {"price": 67234.5, "change_pct": 2.1, "volume_24h": 1234567}}
```

### tracker.py — Position Lifecycle

`Tracker` runs every poll cycle. It fetches balances, computes PnL, auto-claims rewards above the threshold, and auto-withdraws positions that fall below the floor.

```
    Tracker.check_all()  (called every poll cycle)
    |
    |  For each active position:
    |
    +---> GET /vision/balance/{block_id}/{player}
    |         from oracle API
    |
    +---> Update balance + PnL
    |
    +---> PnL > claim_above?  ----YES----> GET BLS signature
    |         |                            from oracle
    |         NO                           |
    |         |                            +---> claimRewards() on-chain
    |         v
    +---> balance < withdraw_below? --YES--> GET BLS signature
    |         |                              from oracle
    |         NO                             |
    |         |                              +---> withdraw() on-chain
    |         v                                    |
    +---> Save to pnl.json                         +---> Remove from active
```

Key config knobs:

| Config Key | Default | Effect |
|------------|---------|--------|
| `auto_claim` | `true` | Automatically claim when PnL exceeds threshold |
| `auto_withdraw` | `true` | Automatically withdraw depleted positions |
| `claim_above` | `5` | Claim when profit exceeds N USDC |
| `withdraw_below` | `2` | Withdraw when balance drops below N USDC |
| `pnl_file` | `pnl.json` | File to persist position state across restarts |

## Bot Lifecycle

Poll → Predict → Join → Monitor → Claim → Sleep. The main loop in `bot.py` calls `run_cycle()` every `poll_interval` seconds.

```
    +============================================================+
    |                    MAIN LOOP (bot.py)                       |
    |                                                            |
    |    +--------+     +----------+     +--------+              |
    |    |  POLL  |---->| PREDICT  |---->|  JOIN  |              |
    |    +--------+     +----------+     +--------+              |
    |        |               |               |                   |
    |        |  fetch_       |  strategy     |  1. approve USDC  |
    |        |  blocks()    |  .predict()   |  2. depositBalance|
    |        |               |               |  3. joinBlock()   |
    |        |  fetch_       |  encode_      |  4. submit_bitmap |
    |        |  block_config |  bitmap()     |     to oracles    |
    |        |               |               |                   |
    |        |  feed.        |  hash_        |  tracker          |
    |        |  subscribe()  |  bitmap()     |  .on_join()       |
    |        |               |               |                   |
    |    +--------+     +----------+     +--------+              |
    |    |MONITOR |---->|  CLAIM   |---->| SLEEP  |---+          |
    |    +--------+     +----------+     +--------+   |          |
    |        |               |                        |          |
    |        |  tracker      |  BLS-signed            |          |
    |        |  .check_all() |  balance proofs        |          |
    |        |               |                        |          |
    |        |  fetch PnL    |  claimRewards()        |  poll_   |
    |        |  from oracles |  or withdraw()         |  interval|
    |        |               |  on-chain              |          |
    |        |               |                        |          |
    |        +---------------+------------------------+          |
    |                                                   (loop)   |
    +============================================================+
```

### Phase 1: Poll

Find candidate blocks. The framework tries three sources in order:

1. **Oracle API** — `GET /vision/blocks`.
2. **`vision-blocks.json`** — static file from contract deployment.
3. **On-chain scan** — read `nextBlockId()` and iterate.

Then filter:

- Already joined (`tracker.active_ids`).
- Already joined on-chain in a previous run.
- Block paused.
- `block_ids` allowlist (if set).
- `min_block_id` floor.
- `max_blocks` capacity reached.

### Phase 2: Predict

For each eligible block, the framework fetches the market list, subscribes to the WebSocket feed for live prices, and calls `strategy.predict(markets)`.

The returned `["UP", "DOWN", ...]` list is encoded into a bitmap and hashed with `keccak256`.

### Phase 3: Join

Joining is four transactions, handled automatically:

```
    USDC.approve(Vision, amount)
         |
         v
    Vision.depositBalance(amount)    <-- credits your Vision balance
         |
         v
    Vision.joinBlock(                <-- locks deposit + records bitmap hash
        blockId, configHash,
        depositAmount, stakePerTick,
        bitmapHash
    )
         |
         v
    POST /vision/bitmap              <-- reveals actual bitmap to oracles
         to all oracle nodes
         (with retry + backoff)
```

### Phase 4: Monitor

`tracker.check_all()` runs every cycle:

- Fetch current balance from the oracle API.
- Compute PnL = `current_balance - deposited`.
- Auto-claim if profit exceeds `claim_above` (requires a BLS signature from the oracle).
- Auto-withdraw if balance falls below `withdraw_below`.

### Phase 5: Sleep

Sleep for `poll_interval` seconds (default 30), then loop.

## Strategy Development

A strategy is a Python class with a `predict()` method. The framework finds it by name and instantiates it on startup.

### Creating a New Strategy

1. Create a file in `vision-bot/strategies/`:

```python
# strategies/mean_reversion.py
from framework.core import Strategy


class MeanReversionStrategy(Strategy):
    name = "mean-reversion"

    def predict(self, markets: list[dict]) -> list[str]:
        """Bet against recent momentum -- contrarian approach."""
        bets = []
        for m in markets:
            change = m.get("change") or 0
            # If it went up recently, bet DOWN (expect reversion)
            if change > 0:
                bets.append("DOWN")
            else:
                bets.append("UP")
        return bets
```

2. Set `strategy = "mean-reversion"` in your `config.toml` (or the `STRATEGY` env var).

The loader in `core.py` scans every module in `strategies/`, finds the class whose `name` matches, and instantiates it.

### Strategy Stack

```
    config.toml
    strategy = "momentum"
         |
         v
    +-------------------+
    | load_strategy()   |   core.py
    |                   |
    | Scans strategies/ |
    | for name match    |
    +--------+----------+
             |
             v
    strategies/
    +---------------------------------------------+
    |                                             |
    |  random_strategy.py   name = "random"       |
    |  momentum.py          name = "momentum"  <--+-- match!
    |  mean_reversion.py    name = "mean-reversion"|
    |  your_strategy.py     name = "your-name"    |
    |                                             |
    +---------------------------------------------+
             |
             v
    +-------------------+
    | Strategy instance |
    |                   |
    | .predict(markets) |---> ["UP","DOWN","UP",...]
    +-------------------+          |
                                   v
                          encode_bitmap() -> bytes
                                   |
                                   v
                          hash_bitmap()   -> keccak256
```

### The `predict()` Contract

`predict()` receives a list of market dicts and returns one string per market — `"UP"` or `"DOWN"` — in the same order.

**Input** — each market dict:

```python
{
    "id": "bitcoin",          # asset identifier
    "price": 67234.50,        # current price (float)
    "change": 2.1,            # percent change (float or None)
    "volume": 1234567890.0,   # 24h volume (float or None)
    "market_cap": None,       # market cap (float or None)
}
```

**Output** — list of strings:

```python
["UP", "DOWN", "UP", "UP", "DOWN", "UP", ...]
```

The framework handles everything after `predict()` returns: encoding, hashing, on-chain submission, bitmap reveal.

### Bundled Strategies

| Name | Logic |
|------|-------|
| `random` | `random.choice(["UP", "DOWN"])` per market. Baseline. |
| `momentum` | UP if `change >= 0`, else DOWN. Follow the trend. |

### Using the Feed in Strategies

Strategies that need historical data can accept `VisionFeed` as a constructor argument. The bot's main loop passes it through:

```python
class HistoryStrategy(Strategy):
    name = "history-aware"

    def __init__(self, feed=None):
        self.feed = feed

    def predict(self, markets):
        bets = []
        for m in markets:
            if self.feed:
                hist = self.feed.history("current_block", m["id"])
                if len(hist) > 10:
                    avg = sum(p["price"] for p in hist[-10:]) / 10
                    bets.append("UP" if m["price"] < avg else "DOWN")
                    continue
            bets.append("UP")
        return bets
```

## Configuration

### config.toml

The framework loads configuration from `config.toml`. Every value can be overridden by an environment variable. Full reference:

```toml
# Strategy
strategy = "momentum"         # Name of strategy class to load

# Deposit sizing
deposit = 10                   # USDC per block (whole tokens, scaled to 18 dec internally)
stake = 1                      # USDC staked per tick

# Risk limits
max_blocks = 50               # Max concurrent block positions
max_exposure = 1000            # Max total USDC across all positions

# Polling
poll_interval = 30             # Seconds between cycles

# Auto-lifecycle
auto_claim = true              # Claim rewards automatically
auto_withdraw = true           # Withdraw depleted positions
claim_above = 5                # Claim when profit exceeds N USDC
withdraw_below = 2             # Withdraw when balance drops below N USDC

# Endpoints
rpc_url = "http://localhost:8545"
vision_api = "http://localhost:10001"
data_node = "http://localhost:8200"

# Oracle discovery
oracle_discovery = "static"    # "static" or "dynamic" (on-chain registry)
oracle_urls = [
    "http://localhost:10001",
    "http://localhost:10002",
    "http://localhost:10003",
]

# Block filtering
block_ids = []                 # Empty = join any block. [1, 3, 7] = only these.

# Persistence
pnl_file = "pnl.json"
```

### Environment Variable Overrides

Every config key has an env var equivalent. Env vars win when both are set:

```

    | strategy = "random"   | <---- | STRATEGY=momentum       |
    | deposit = 10          | <---- | DEPOSIT_AMOUNT=25       |

    | max_exposure = 1000   | <---- | MAX_EXPOSURE=200        |
    | poll_interval = 30    | <---- | POLL_INTERVAL=60        |

    | vision_api = "..."    | <---- | VISION_API_URL=https:// |
```

## Risk Management

The bot enforces two hard limits before joining any block. If either fails, the block is skipped.

### RiskCheck

`RiskCheck` enforces two limits:

```
    RiskCheck
    +--------------------------------------------------+
    |                                                  |
    |   max_blocks = 10        max_exposure = 500     |
    |                                                  |
    |   .can_join(deposit) checks:                     |
    |     1. active_count < max_blocks?               |
    |     2. total_exposure + deposit <= max_exposure?  |
    |                                                  |
    |   Both must pass. Otherwise the block is skipped.|
    |                                                  |
    +--------------------------------------------------+
    |   Active positions:                              |
    |   +--------+----------+                          |
    |   |Block ID| Deposit  |                          |
    |   +--------+----------+                          |
    |   |   1    | 50 USDC  |                          |
    |   |   3    | 50 USDC  |                          |
    |   |   7    | 50 USDC  |                          |
    |   +--------+----------+                          |
    |   Total: 150 / 500 USDC                          |
    |   Count: 3 / 10 blocks                          |
    +--------------------------------------------------+
```

### Additional Safety Checks in bot.py

The main loop applies eight more guards before joining a block:

```
    New block candidate
         |
         v
    +-- block_id < min_block_id? -----> SKIP
    |
    +-- block_id in tracker.active? --> SKIP (already tracking)
    |
    +-- block_ids set and block_id
    |   not in allowlist? ------------> SKIP
    |
    +-- block.paused? ----------------> SKIP
    |
    +-- tracker.active >= max_blocks?-> SKIP (at capacity)
    |
    +-- Already joined on-chain? -----> SKIP (previous run)
    |
    +-- risk.can_join(deposit)? ------> SKIP (exposure limit)
    |
    +-- usdc_balance < deposit? ------> SKIP (insufficient funds)
    |
    v
    PROCEED TO JOIN
```

<Warning>
**Capital is at risk.** Every USDC deposited is staked against other players. Consistently wrong predictions drive the balance toward zero. `auto_withdraw` exits positions before depletion, but losses are real and irreversible.
</Warning>

### Recommended Risk Settings

New bot, small capital — losses you can absorb while testing:

```toml
deposit = 5            # Small deposits while testing
stake = 1              # Minimum viable stake
max_blocks = 3        # Few concurrent positions
max_exposure = 50      # Hard cap on total exposure
auto_claim = true      # Take profits automatically
auto_withdraw = true   # Exit losing positions
claim_above = 3        # Claim small profits early
withdraw_below = 2     # Cut losses quickly
```

Production bot, strategy with measured edge:

```toml
deposit = 50
stake = 5
max_blocks = 20
max_exposure = 2000
auto_claim = true
auto_withdraw = true
claim_above = 10
withdraw_below = 5
```

## Running the Bot

### Basic Usage

```bash
# Set required env var
export BOT_PRIVATE_KEY="0xYOUR_PRIVATE_KEY"

# Run with default config.toml
cd vision-bot
python bot.py

# Run with a specific config file
python bot.py --config path/to/config.toml

# Run a single cycle (useful for testing / cron jobs)
python bot.py --once
```
