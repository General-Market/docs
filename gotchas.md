# Gotchas

Patterns that bit us. Written to prevent repeats.

## Infrastructure

- **Disk full on a shared host is never one failure**. Postgres dies, pgbouncer caches connections and keeps reporting healthy, data-node swallows stale reads, oracles starve silently. When the disk recovers, every DB on that host — Postgres, Blockscout's private PG, Nitro's pebble/freezer, RocksDB, anything that writes — must be integrity-checked. The Apr 12 outage broke Postgres and Nitro's freezer tables. Recovery fixed the first, missed the second for three days.
- **"Healthy" heartbeats lie when the work is zero**. `orders_processed=0 health_status=healthy` is not health. Every long-lived service must expose a `did-you-do-work` endpoint that tracks throughput over a window. Presence of process ≠ presence of function.
- **Docker default log driver has no size cap**. A single nginx proxy container filled 65 GB on VPS 1 before we noticed. Install `/etc/logrotate.d/docker-container` on every host that runs Docker, use `copytruncate`, 50 MB × 5.
- **pgbouncer reports healthy while its upstream is dead**. It answers its own TCP handshake. Real health is `SELECT 1` round-tripping to the backend.

## Configuration

- **Mock exchange against real chain is a distinct failure class**. If `exchange_mode=mock` while `chain_mode=real`, fail-fast at startup. Never trust manual env correctness across environment switches. The AP spent days flipping testnet orders through a mock Bitget because nobody wired the interlock.
- **Docker Compose `${VAR}` in `environment:` interpolates from HOST shell, not `env_file`**. Unsourced variables silently become empty strings. Use `env_file:` exclusively for secrets; `environment:` only for static values.
- **env_file layering order matters**. Load `.env` then `system.env` as override. If reversed, secrets from `system.env` get stomped. Data-node lost Bitget creds this way.

## Oracles & Consensus

- **Log lines like `INFO ... signer_count=0 ... consensus agreed` are placeholders, not facts**. Verify against on-chain state (emitted events, stored signatures) before concluding BLS is bypassed. The Apr 14 investigation wasted hours here until `cast logs` confirmed real signatures. Fix the log, don't the code — but fix the log. NAV branch done (`ee97857a`), price branch pending.
- **Oracle P2P WAL is unbounded by default**. Errors `INFRA-022 WAL exceeded 10 MB, disabling writes` mean replay recovery is now broken. Add disk-bounded rotation before it degrades silently.

## Events & Ordering

- **`N` events vs `nextOrderId=N+1` is the correct invariant, not a bug**. `nextOrderId` is the ID that will be assigned next. The Apr 14 "111 ghost orderIds vs 112 nextOrderId" panic was just the off-by-one. Always subtract one before claiming a gap.

## MetaMorpho / Curator

- **"Wrong address" can mean "no address"**. If `eth_getCode` returns `0x` at the vault you're curating, the vault was never deployed — not redeployed elsewhere. Curator must check code length at startup and refuse to run against zero-code addresses.

## Chain-level

- **Nitro freezer table corruption survives container restart**. A clean Docker restart loop on `orbit-l3-testnet-sequencer-1` with `Failed to open database: freezer table ... is corrupted` means the pebble DB's ancient segments are torn. Only fixes: restore snapshot, or full L1 resync. No config edit will help.

## Parallel Agents

- **`git add` then `git commit` is not safe when multiple agents share the working tree**. The index is shared state. Agent A stages its file, Agent B stages its file before A commits, then A's `git commit` sweeps both into one commit — and B's later `git commit` finds nothing to do. Symptom from May 4 swarm: the UpNextRail diff landed inside the OnboardingCompass agent's commit (`7e6da13d`), with the wrong subject line. Work shipped, attribution drifted. Fix: every agent uses the atomic form — `git commit -m "<msg>" -- <path>` — which stages and commits the named paths in one operation. The index outside those paths is left untouched. No `git add` step at all.
- **`git checkout HEAD -- <file>` destroys a co-worker's uncommitted edits to a shared file**. When two agents both edit `Root.tsx` and one is committed, the other still lives only in the working tree. Using `git checkout HEAD -- Root.tsx` to "reset before re-applying my hunks" silently deletes the uncommitted half. May 23 symptom: the `AntiCheatEdit` composition registration vanished (`Composition with ID AntiCheatEdit not found`) because the registration was a working-tree-only edit while its component files were already committed. Fix: never `checkout`/`restore` a shared file to split hunks — add the new file paths atomically and leave the shared file as-is, or re-apply the wiped edits by hand. The composition `.tsx` being committed does NOT mean its `Root.tsx` registration is committed; check both.

## Oracle Redeploy

- **`redeploy-oracle.sh` removed the containers BEFORE building — a failed build = dead oracles** (2026-05-24). The script's step 2 did `docker rm -f testnet-oracle-{1,2,3}` (a direct `docker rm`, no compose needed), THEN step 3 built. When step 3 failed, the oracles were gone with no path back. Rule: **build first, swap only after the new image exists.** A rebuild must never be able to take prod down. Fixed by reordering the script (build → then remove+recreate).
- **`docker/testnet/oracle/docker-compose.override.yml` is a generated artifact, not in git, and gets cleaned**. `testnet.sh _start_oracles_docker` writes it (per-oracle `command:`, key-file `volumes:`, env incl. Bitget). The base `docker-compose.yml` has *only* build+network+logging — without the override the oracles have no command and no key mounts and cannot start. A created container keeps its config independent of the file, so deleting the override doesn't stop running oracles — it only blocks **recreation**. The override was cleaned May 21; the oracles ran fine until they were removed May 24, then couldn't be recreated. Fix: `scripts/gen-oracle-override.py` regenerates it from `active-deployment.json` + `system.env` (mirrors testnet.sh); `redeploy-oracle.sh` now regenerates if missing and aborts before any destructive step if it still can't.
- **The oracle key files are NOT the BLS keys**. `/tmp/oracle-key-N.txt` + `/tmp/settlement-key-N.txt` are the ECDSA tx-signing keys (mounted read-only). The BLS keys are derived deterministically from `--test-key-seeds` + `--bls-key-seed-index N`. So regenerating the override (which references the key files) is safe and does NOT touch BLS — but running `_start_oracles_docker` does rewrite the key files from `$ORACLE_KEYS`, so never run that function without the full testnet.sh env or you'll blank the tx-signing keys.

## Frontend / Responsive

- **An inline `display` defeats a responsive `hidden`/`lg:hidden` class** (2026-05-24). On the human-trading source page the new `MobileActionBar` carried `className="lg:hidden"` but also `style={{ display: 'flex' }}` for its column layout. Inline styles beat classes, so `display:flex` won at every width — the bar leaked onto desktop, doubling the entry control beside the rail. Rule: when a responsive `*:hidden` must be able to hide an element, never set `display` inline. Put the layout in classes (`flex flex-col lg:hidden` — Tailwind emits the `lg:` variant after the base utility, so it wins at the breakpoint). The old MobileValidate worked only because it had no inline `display`.
- **`position: fixed` anchors to the nearest `filter`/`transform`/`backdrop-filter` ancestor, not the viewport** (2026-05-24). AppShell wraps the page in a `filter` ancestor, so a fixed bottom bar rendered in-tree stuck to the bottom of the page *content* — below the footer — instead of the screen edge. The validate button existed but was unreachable without scrolling past everything; this is part of why betting felt impossible on phones. Fix: portal the bar to `document.body` (same trick `HumanTradingOnboarding` already used — guard with a mounted `portalEl` state to avoid SSR/hydration mismatch). When a fixed element won't pin to the viewport, look up the tree for a filter/transform before touching z-index.
- **A laptop fold is ~760px usable, not the 900px CSS height a Retina screen reports**. Maximized Chrome on a 13" MacBook leaves ~760px after the menu/tab/address bars. Fit-in-one-screen work on the source page targets that: candle chart body is `clamp(180px, 27vh, 290px)` so it scales with the viewport, mini-card sparkline is `SPARK_H` (84px), card padding/gaps tightened. Verify with the browser at 768/900, not by arithmetic alone.
- **lightweight-charts autoscales the price axis to the series data ONLY — price lines and overlay divs do not widen it** (2026-05-24). On the Vision candle chart (`MarketCandleChart.tsx`) the threshold marker, blue zone, and dashed settle line are HTML overlays positioned with `priceToCoordinate(threshold)`. The threshold is `open × (1 ± bps/10000)`, so with a real bps offset it sits a few percent off the recent candles — and the chart's autoscale, which fits the candles alone, left it off the top/bottom of the plot. `priceToCoordinate` then returns a coordinate *outside* `[0, height]` (it extrapolates, it does not clamp to null), so the overlay renders off-screen. The default-selected market happened to have a near threshold, which masked it — clicking other markets exposed it. The small recharts cards never had this because they explicitly push `sq.price` into the Y-domain. Fix: give the candlestick series an `autoscaleInfoProvider` that calls the original range and widens it to include the threshold + open/close — the Y-axis twin of the recharts yDomain padding. Declare the provider-install effect BEFORE the marker/zone effects so the scale is already widened when they read coordinates, and pass a fresh provider closure each time to force the series to recompute. Rule: any overlay or marker placed by `priceToCoordinate`/`timeToCoordinate` is only correct if its value is inside the auto-fitted range — when you place a mark off the data, you must teach the scale to include it (autoscaleInfoProvider), or it silently leaves the viewport. Verify by selecting MULTIPLE series, not just the default one.
- **A flat market (0.00% this round) hides whether a price→threshold fill works** (2026-05-24). Adding the blue target-zone rectangle to the Vision source cards (`HumanMarketCard.tsx`), the fill appeared on only 2 of 10 cards. Measuring the SVG showed the cause: every card had `lastDataY === threshY` — the current price sat exactly on the threshold, so the zone was zero-height. The markets simply hadn't moved this round (`0.00%`). A zero-height rect is invisible whether recharts emits a degenerate path or nothing, so the "2 of 10" was noise, not a bug. The big candle chart's selected market *had* moved and its zone filled with real 25px height — that's what proved the code. Rule: to verify a fill/area that spans current-value → some-target, find or wait for a row where the two differ; checking it against a quiet market tells you nothing. Measure `Math.abs(target - current)` per row and confirm every row with a real gap draws, rather than counting how many drew. The accompanying `ifOverflow="visible"` on the recharts `ReferenceArea`/`ReferenceLine` is correct insurance for when the zone's right edge lands exactly on the X-domain max — but it was not why the flat-market zones were empty; don't conflate "discarded at the domain edge" with "zero-height."

## Destructive cleanup

- **`rm` globs for your own scratch files can name a pre-existing untracked file — check `git status ??` first** (2026-05-24). While deleting my own `bridges-*.png`/`local-*.png` screenshots I also named `anticheat-before-play.jpeg` in the same `rm`, assuming it was mine. It was an untracked file present before the session (it showed as `?? anticheat-before-play.jpeg` in the opening git status). Untracked = not recoverable from git, and `rm` skips Trash. Rule: before deleting scratch artifacts, delete only paths you created this session by exact name; never sweep a glob or a name you didn't write, and cross-check the opening `git status` for `??` files you didn't author.

## 2026-06-06 — workflow synthesis stalls + a watchdog that cried wolf
- **Symptom:** Workflow synthesis agents with ~350KB prompts generating ~130KB outputs stalled repeatedly (no progress 900s, 5 retries, then socket close). Agents with ~240KB prompts succeeded in minutes.
- **Rule:** Cap any single workflow agent at roughly ≤150KB prompt + ≤70KB expected output. Split big synthesis into parts that each receive ONLY the draft slice they synthesize from, with headings that concatenate.
- **Rule:** On macOS the default `find` is `bfs` — `-newermt "-300 seconds"` is an invalid timestamp and the error makes the match list empty, which a naive watchdog reads as "stalled". Use `stat -f %m` epoch math. A watchdog that can error into its alarm state is worse than none.
- **Note:** Workflow resume cache keys broke for an unchanged agent call after sibling calls in the same parallel() changed — don't count on a cache hit to avoid re-running an expensive agent; salvage its result from `journal.jsonl` (`.result` on `"type":"result"` entries) instead.

## twapi.py advsearch always 408 — multiprocessing queue deadlock (2026-06-06)
`_get()` did `p.join(timeout)` BEFORE reading the result queue. A forked child's `q.put()` blocks when the payload exceeds the pipe buffer (~64KB) until the parent reads — so every large response (advanced_search pages) deadlocked into the 30s hard timeout while small ones (balance, userinfo) passed. Fix: `q.get(timeout=...)` first, then join. Rule: with multiprocessing Queues, always drain before join.

## twitterapi.io key lives nowhere durable (2026-06-06)
/tmp/.twapi_key vanishes on reboot; xwatch/.env has the var EMPTY; not in keychain. Recovered the `new1_…` key from old session transcripts. Also: `twapi.py balance` serves a CACHED balance (.last_balance.json) — it said $100 when the live balance was $4.14; trust `rebase`/live calls, not `balance`, after a long gap.
