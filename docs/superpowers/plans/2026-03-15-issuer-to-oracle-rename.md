# Oracle → Oracle: Global Rename

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename every occurrence of "oracle" to "oracle" across the entire codebase — contracts, Rust, frontend, Python, Docker, monitoring, scripts, docs, deployments. Clean slate redeployment; no backward compatibility.

**Architecture:** Mechanical `sed` replacement in 11 sequential layers, ordered by dependency (contracts → common → oracle crate → downstream crates → frontend → Python → infra → scripts → docs → meta). Each layer ends with a compile/build gate and a commit. File and directory renames happen *after* content replacement within each layer.

**Tech Stack:** `sed`, `git mv`, `forge build`, `cargo build`, `npx tsc --noEmit`

**Variant map (apply in this order to avoid partial matches):**

| Pattern | Replacement | Flags |
|---------|-------------|-------|
| `OracleRegistry` | `OracleRegistry` | case-sensitive |
| `IOracleRegistry` | `IOracleRegistry` | case-sensitive |
| `IMirrorOracleRegistry` | `IMirrorOracleRegistry` | case-sensitive |
| `MirrorOracleRegistry` | `MirrorOracleRegistry` | case-sensitive |
| `OracleCustody` | `OracleCustody` | case-sensitive |
| `oracle_registry` | `oracle_registry` | case-sensitive |
| `oracle_health` | `oracle_health` | case-sensitive |
| `oracle-nodes` | `oracle-nodes` | case-sensitive |
| `ORACLE` | `ORACLE` | case-sensitive |
| `Oracles` | `Oracles` | case-sensitive |
| `Oracle` | `Oracle` | case-sensitive |
| `oracles` | `oracles` | case-sensitive |
| `oracle` | `oracle` | case-sensitive |

**Order matters.** Longer patterns first prevents `OracleRegistry` from becoming `OracleRegistry` via the compound rule AND then `OracleOracleRegistry` via the simple rule.

**Exclusions (never touch):**
- `target/` — Rust build artifacts (regenerated by `cargo build`)
- `contracts/out/` — Foundry build output (regenerated by `forge build`)
- `.claude/worktrees/` — ephemeral worktrees
- `logs/` — historical log files
- `node_modules/` — npm dependencies
- `.git/` — git internals

**sed cannot catch (manual fixes required):**
- Hardcoded hex selectors (raw `[0x..]` bytes derived from function names)
- External state: VPS nginx configs, Vercel env vars, GitHub Actions secrets, VPS database tables

- [ ] **Step 2: CRITICAL — Fix hardcoded hex selector in health_monitor.rs**

sed renamed the constant NAME and COMMENT but not the raw bytes. The new function `activeOracleCount()` has selector `0xbca86af8`.

**PRE-EXISTING BUG:** The existing bytes `[0x9f, 0x6e, 0x3a, 0x2d]` do NOT match `keccak256("activeOracleCount()")` which is `0x10ccc4a7`. The old selector was wrong — the curator's `rpc_read_l3_active_oracle_count()` has been silently returning 0 (RPC call to non-existent selector → empty response → default 0). After installing the correct selector, this function will return REAL data. Verify that no code path depends on this value always being 0.

```bash
sed -i '' 's/\[0x9f, 0x6e, 0x3a, 0x2d\]/[0xbc, 0xa8, 0x6a, 0xf8]/' curator/src/health_monitor.rs
```

Verify: `grep 'SELECTOR_ACTIVE_ORACLE_COUNT' curator/src/health_monitor.rs` should show `[0xbc, 0xa8, 0x6a, 0xf8]`.
